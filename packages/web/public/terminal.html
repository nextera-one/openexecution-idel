    Knowledge Base

    Detecting OS guidance for batch, wait, native, elevation, and packages

    Batch Commands

    Use top-level && to run IDEL commands one after another. The next step starts only after the previous step succeeds. 

    create.folder name=demo && create.file name=demo/readme.md && read.file name=demo/readme.md

    Turn on the Batch input toggle for multiple lines, then use Ctrl+Enter to run. A native line that starts with ! is kept as one shell command, so && inside it belongs to the shell.

    Wait Between Steps

    Use wait.time when a batch needs a short pause before the next command reads a file, checks a log, or talks to a service. 

    run.script path=./scripts/start.sh shell=bash && wait.time seconds=2 && tail.file file=app.log lines=40
    create.file name=ready.txt && wait.time ms=500 && read.file name=ready.txt

    Native Passthrough

    Use ! when you need a real OS command that IDEL does not model yet. It is still risk-scanned, policy-checked, and logged, but it is less structured than a native IDEL command. 

    ! sudo apt install git
    ! "sudo apt install git"

    The quoted form is accepted for convenience. IDEL sends both examples to the shell as sudo apt install git. 

    sudo apt install git

    For interactive commands, open a sh tab. Native shell tabs send Tab, arrows, Ctrl+C, and password prompts directly to the OS shell.

    Elevation And Packages

    Package-manager commands should be explicit because search, install, remove, upgrade, and source edits have very different risks. Prefer curated IDEL commands when available; use ! for one-off native work. 

    ! sudo apt update
! sudo apt install git
! apt search git

    Interactive sudo password prompts work best in a real terminal. In the web terminal, prefer commands that do not need an interactive password prompt, or run the server from a session where sudo is already ready.

    Clear Scrollback

    Clear commands affect only the visible rows in the active terminal tab. They do not delete files, audit logs, or command history. 

    clear.all
clear.last limit=10
clear.first limit=5
clear.range from=2 to=8

    clear.range uses 1-based row numbers and includes both ends of the range.

    Learning CLIs

    learn.cli drafts commands from help text. Some tools, like apt, expose broad subcommands without enough safe parameter detail, so learning may produce no accepted definitions. 

    learn.cli cli=git write=true
learn.cli cli=apt

    Good apt mappings should be curated, for example search.apt.package, show.apt.package, update.apt.index, and install.apt.package, each with its own risk and approval rules.
